# Eval: labeling set and measuring stick

Every accuracy number shown anywhere (README, UI, Method page) comes from a
real run saved to `eval/results/latest.json`. No invented numbers, ever.

## The one rule that protects the measurement

**The test set is never used while building.** `split.json` divides the labeled
postings into a dev set (used while improving the classifier) and a test set
(used only for the final reported score). Tuning against the test set makes the
number a lie. `eval/run.ts` refuses to print test-set results unless
`--report-test` is passed, and any change to `split.json` must be a deliberate,
separate commit.

## Labels

Every posting gets exactly two labels, written by a human.

### a) `text_stance` — what the posting itself says

| label | meaning |
|---|---|
| `sponsors` | The posting says they sponsor visas or invite international applicants. |
| `no_sponsorship` | The posting says they will not sponsor. |
| `requires_authorization` | The posting requires the candidate to already have work authorization, without saying anything about sponsorship either way. |
| `citizenship_or_clearance` | The posting requires citizenship or a security clearance. |
| `silent` | Nothing either way. This is the most common case and a perfectly good answer. |

**`sponsors` — real examples**

- Lovable (full-stack engineer, Stockholm/London): "we sponsor visas and have
  very generous relocation packages."
- Any posting whose requirements section says "visa sponsorship available" or
  "we welcome international applicants".

**`no_sponsorship` — real examples**

- PrairieLearn (software developer): "not able to sponsor".
- Solace Health: "No visa sponsorship" as a hard requirement line.

**`requires_authorization` — real examples**

- A posting saying "must be authorized to work in the US" with nothing about
  whether the company sponsors.
- "Candidates must have the right to work in the UK."

**`citizenship_or_clearance` — real examples**

- Stellar Science (internship, Albuquerque NM): "U.S. citizenship required".
- Thoughtworks (Singapore): role "requires the successful candidate to be a
  Singapore Citizen OR Singapore Permanent Resident only" because of client
  security clearance.

**`silent` — real examples**

- Most internship postings: they list skills, term and location and never
  mention visa status at all.

### b) `overall_verdict` — the human's judgment

| label | meaning |
|---|---|
| `open` | An international applicant can apply as-is: explicit sponsorship, worldwide remote, or hiring in regions that include them. |
| `likely` | The posting is silent, but the employer has a real history of sponsoring. |
| `unclear` | Not enough evidence either way. Valid and common. Do not force a guess. |
| `unlikely` | Explicit refusal, existing-authorization requirement, or citizenship/clearance. |

`overall_verdict` may weigh things the posting text does not contain (company
reputation, the employer's country). When the posting is explicit, the two
labels normally agree; when they disagree, that disagreement is interesting —
label what you actually believe.

### Verdict evidence rule (for silent postings)

For a posting whose `text_stance` is `silent`, a verdict other than `unclear`
requires a verbatim quote about **visas, work authorization, relocation
support, or explicit worldwide / any-country hiring**. These do NOT qualify:

- location-only restrictions ("remote in Europe", "US-based preferred")
- equal-opportunity / diversity statements ("we celebrate 50 nationalities")
- benefits (insurance, equipment, health cover)

"Location-restricted remote" is future work for the **Reach screen**, not a
label here.

## Files

| file | what it is |
|---|---|
| `postings.jsonl` | The 300-posting sample, generated by `eval/sample.ts` from `data/fulltext.jsonl`. Random order, companies capped at 5. |
| `labels.jsonl` | One line per labeled posting: `{id, hash, text_stance, overall_verdict, revisit, labeledAt}`. `hash` is a SHA-256 prefix of the posting text, so a stale label (text changed since labeling) can be detected. |
| `split.json` | The dev/test split and the seed that produced it. |

## Baselines (majority class) — natural set only, never pooled with stratified

Any classifier must beat these to be worth anything. From `labels.jsonl`:

| baseline | full natural (300) | dev (200) | test (100) |
|---|---|---|---|
| always answer `silent` (text_stance) | **88.0%** (264/300) | 89.5% (179/200) | 85.0% (85/100) |
| always answer `unclear` (overall_verdict) | **75.3%** (226/300) | 79.5% (159/200) | 67.0% (67/100) |

The `always unclear` number holds only because exactly **38** postings say
nothing about visas yet carry a verdict other than `unclear` (27 `open`,
11 `likely`). All 38 carry a verbatim posting quote behind the verdict and all
38 are in the audit queue. Any one the audit rejects loses its quote and
becomes `unclear` + `verdict_ai_prior`, which raises the baseline.

## Metrics (what the runner reports, per set)

Natural and stratified sets are scored separately, never pooled. Headline
metrics, each with a 95% Wilson interval (`eval/stats.ts`) and its n:

1. **Statement detection** — precision and recall of non-silent vs silent.
2. **Stance accuracy among detected statements** — of the postings the engine
   correctly says are non-silent, how often the stance is right.
3. **`blocked` precision/recall** — blocked = no_sponsorship +
   requires_authorization + citizenship_or_clearance (merged class, because
   each fine-grained class alone is too rare to measure).
4. **`sponsors` precision/recall.**

Fine-grained per-class stance scores are secondary and marked small-n.

## Tricky cases

`eval/tricky_cases.jsonl` — named negative cases: real boilerplate that looks
like sponsorship language but is not. The engine must classify every one as
`silent`. Currently: the Cloudflare export-license clause (58 postings carry
it), Datadog's export-control "authorizations", EEO protected-class
"citizenship status" lists (21 postings), Substack's product "sponsorship
opportunities", Binance's "Visa" the payment network, domestic "relocation
assistance" without visa context, and a synthetic sponsor-as-job-title case.

## Two-pass consistency

Labels were produced in two independent AI passes (`labels.jsonl`,
`labels-passB.jsonl`; both passes blind to each other). Self-consistency, not
human agreement — see `eval/agreement.json`. The 76 disagreements are all in
the audit queue.

## Label provenance

The current 300 labels were authored by an AI agent (Claude) following this
rubric, at the repo owner's request, not by the human directly. The accuracy
numbers downstream must be read with that in mind. To review or override any
label: remove its line from `labels.jsonl` (or all lines), run `npm run label`,
and relabel by hand — the tool is the human path and it overwrites on save.

## Labeling tool

```bash
npm run label      # serves http://localhost:4177
```

Blind by design: it shows the posting text with sponsorship keywords
highlighted and nothing else. Keys: `1–5` text_stance, `q w e r`
overall_verdict, both chosen auto-saves, `space` skip, `u` revisit flag,
`z` undo. Labels are saved to disk after every one.

## Audit queue

```bash
npm run audit      # serves http://localhost:4178
```

The queue (`eval/audit-queue.json`, seed 20261019) contains every posting
where a human judgment is worth most: all non-silent labels, the
revisit-flagged ones, every pass A / pass B disagreement, every silent posting
that kept a non-unclear verdict, and 40 random silent postings. Three keys:
`a` accept, `w` wrong (relabel inline), `s` unsure. Results go to
`eval/audit-results.jsonl`.

## Stratified rare-class set

The natural 300-sample is almost all `silent` (the real distribution), which
leaves the rare stances too thin to measure. `eval/stratified/` holds extra
postings found by keyword search over the full snapshot (no engine output
used), labeled through the same two blind passes with verbatim quotes.
It is scored separately from the natural set, never mixed into its accuracy.
Shortfall, honestly stated: the snapshot contains only 32 confirmable
rare-class postings (5 `no_sponsorship`, 8 `requires_authorization`, 19
`citizenship_or_clearance`), well under the 30-per-class target. Getting to 30
per class needs more explicit-refusal postings than this snapshot has — that
means new sources (Phase 3), not more keywords.
